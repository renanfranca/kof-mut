## Delivered behavior and boundaries

`install.sh` protects child creation/registration with pending cancellation and a readiness/release handshake. Preparation is not released until the coordinator knows the child and session. Cleanup addresses the PID and group and reaps the child. A scoped refactor-design review read the complete rubric after focused public journeys were green: **design risk** was the in-flight readiness read sharing the confirmed cleanup group field. A separate read value now makes the complete-record boundary explicit. No additional structural change was justified: invocation properties have one process lifetime, manifest context travels explicitly, ownership remains inside the management lease, and repeated checks cross compilation/persistence or deliberately detect fresh checkout changes.

The Bash launch bridge hashes each captured input once and derives both the unchanged compilation request and a separate private package manifest from those hashes. The package inventory covers installation/build/launch scripts, VERSION, manifest, production sources, LICENSE, NOTICE, READMEs and all docs. `RuntimeEntry` verifies the compilation identity and manifest subset against the selected image, reads the context before deleting the handoff, and passes the context to Kof installation. Kof checks the actual copied bytes and rechecks the full participating file set/content after image probes, before publication, ownership registration or activation. No later checkout reads compose the prepared image. Detected changes abort with 2 and `checkout changed during installation; retry`; stabilize the checkout and retry. Documentation or install.sh changes can produce a new package while reusing classes.

HOME validation is in the Kof prefix validator, only in the omitted-prefix branch. The existing help shortcut, relative explicit prefixes and overlap/classpath/collision refusals are preserved. CLI flags, evaluation exits and JSON v1 are unchanged. Installed receipts retain `InstalledImage(schemaVersion, prefix, id, inputs, dependency, files)` with schemaVersion 1; the source handoff manifest is private and introduces no public report field.

Kof sources consulted include the parser's test tag handling, file/process implementation and tests, and SHA/file library implementation/tests. Hashing uses the previously proven Files/MessageDigest/HexFormat APIs. All new manifest, copy, error and process flows have executed against the installed 0.6.4 distribution rather than relying on the current Kof source revision's behavior.
